8.0 Message Bases

Synchronet stores public and private posts in message bases organized as groups containing sub-boards (subs). Configuration is primarily SCFG → Message Areas.

Hierarchy

  • Group — named collection (e.g. Local, DOVE-Net, FidoNet echoes) with optional internal code prefix
  • Sub-board — one conference/echo with its own internal code, access ARS, posting ARS, moderated-posting ARS, network settings, and storage options

SCFG menus let you insert/delete groups and subs, set long/short names, and tune per-sub options (anonymous posting, voting, attachment policy, etc. — see the full option list on the wiki).

Sysop practices

  • Keep local-only groups separate from networked echoes so accidental export is harder.
  • Set Operator / Sub-op requirements so trusted users can moderate without full sysop level.
  • Use Moderated Posting User ARS (default deny when blank) when a sub needs review before validation — see Sysop Bible / moderation.
  • Internal codes matter for QWK conference mapping and FTN area tags; choose stable codes before linking networks.
  • After structural changes, recycle as needed and verify with a test post from a non-sysop account.

Message storage lives under data/ (SMB message bases). Do not casually delete those files while sbbs is running.

Wiki: https://wiki.synchro.net/config:message_areas · https://wiki.synchro.net/howto:moderation

9.0 Networking (Messages)

SCFG → Networks covers user-facing and link policy for:

  • Internet e-mail (outbound policy from the terminal mail menu)
  • QWK packet networks (hubs + default tagline)
  • FidoNet EchoMail / NetMail (addresses, semaphores, directories, posting policy)
  • MQTT (status/log publish — monitoring, not classic message networking)

Actual SMTP listening and SendMail are under the Mail Server; FTN packet exchange uses a mailer (e.g. BinkIT) plus SBBSecho.

Wiki: https://wiki.synchro.net/config:networks

9.1 QWK Packet Networking

QWK is a packet format for offline readers and for QWK networking between BBSes (rep message exchange). Synchronet can be a QWK network node calling one or more hubs.

9.1.1 QWK Network Hubs

In SCFG → Networks → QWK Packet Networks you configure:

  • Hubs this BBS calls (and related credentials / paths as documented)
  • Default outgoing tagline (also set under QWK options)

Hub list and per-hub options define where REP packets go and how conferences map. Align hub conference numbers with your local subs carefully — mismatches orphan mail.

Wiki: https://wiki.synchro.net/config:networks

9.1.2 Connect to DOVE-Net

DOVE-Net is the Synchronet community QWK network. High-level steps from the howto:

  1. Choose a QWK-ID — SCFG → Message Options → BBS ID for QWK Packets. Max 8 characters, DOS filename-safe, must start with a letter, unique on DOVE-Net (check nodes.dat in dove-net.zip).
  2. Set your QWKnet tagline (SCFG → Networks → QWK → Default Tagline).
  3. Create a QWKnet account on your hub (commonly Vertrauen — telnet to vert.synchro.net as New). Use the QWK-ID as the username and answer Yes to the QWK Networking (DOVE-Net) question. Remember the password.
  4. At the hub’s QWK: prompt, set packet options to match Synchronet expectations (Ctrl-A leave in, ZIP archive, unread e-mail only, include attachments, etc. — follow the current howto table).
  5. Configure the hub entry locally in SCFG and enable the conferences you want.
  6. To change the QWKnet password later on Vertrauen, login with * prepended to the QWK-ID so you get a full session instead of only the QWK: prompt.

Do not use the web server signup path for the QWKnet account when the howto says to use Telnet.

Wiki: https://wiki.synchro.net/howto:dove-net

9.4 FidoNet

Fido Technology Networks (FTNs) share packet/mailer concepts; this outline section is about joining FidoNet itself. Synchronet bundles the pieces most sysops need (init script, SBBSecho, EchoCfg, BinkIT mailer).

Initial setup options

Pick one:

  1. In-BBS Operator → Initial FidoNet Setup
  2. jsexec init-fidonet.js from a system shell
  3. Windows Control Panel → File → Run → Initial FidoNet Setup

The script asks for zone (1–4 for classic FidoNet geography; other listed zones are othernets), hub address, and your node address (*/9999 temporary is normal until a permanent address is assigned). Have hub hostname/IP, session password, and optional packet/AreaFix passwords ready.

Wiki: https://wiki.synchro.net/howto:fidonet

9.4.1 SBBSecho

SBBSecho is Synchronet’s FTN tosser/scanner — not a mailer. A mailer (e.g. BinkIT) moves packets; SBBSecho imports/exports EchoMail (and, in modern versions, NetMail to/from the Synchronet mail base).

Before configuring, collect:

  • Hub FTN address and Internet hostname/IP
  • Your FTN address
  • BinkP session password; optional packet and AreaFix passwords
  • An EchoList file (e.g. BACKBONE.NA)

SBBSecho v3 overhauled older behavior; prefer current wiki sections labeled for v3. AreaFix, packing, scanning, and import/export paths are all documented at length on the SBBSecho page — use it as the operational manual when packets do not appear in subs.

Wiki: https://wiki.synchro.net/util:sbbsecho

9.4.2 EchoCfg

EchoCfg is the configuration UI companion for SBBSecho (shipped in exec). Use it to maintain linked areas, passwords, and tosser options without hand-editing every INI key. Changes need to match what your hub expects (area names, passwords, packet types).

Wiki: https://wiki.synchro.net/util:echocfg

9.4.3 sbbsecho.ini

The INI file holds SBBSecho’s durable settings (paths, defaults, behaviors). EchoCfg writes here; advanced sysops edit carefully with a backup. Cross-check keys against the wiki’s sbbsecho.ini reference when upgrading major SBBSecho versions.

Wiki: https://wiki.synchro.net/config:sbbsecho.ini

Networking go-live checklist

  • [ ] Local message groups work offline before linking
  • [ ] QWK-ID unique; DOVE-Net account flagged as QWKnet
  • [ ] Fido zone/hub/address and mailer session tested
  • [ ] EchoList imported; AreaFix passwords stored safely
  • [ ] Test post in a quiet echo; confirm round-trip
  • [ ] Moderation ARS understood for networked subs
